# 03 核心模块说明

> 同步日期：2026-05-25  
> 分析范围：`novel_system/` 全模块。

## 1. 架构总览

项目已全面迁移至 **GraphRAG-centric** 架构，舍弃了旧有的混合检索（TF-IDF + FAISS）和防剧透（SpoilerGuard）逻辑。系统通过 GraphRAG 的知识模型（Entities, Relationships, Communities）提供全书维度的深度分析。

```text
api.py (FastAPI 路由)
  -> services/ (业务 Mixin 组合)
       -> indexing.py (GraphRAG 构建流水线)
       -> qa.py (GraphRAG 多模式查询)
  -> graphrag_app/ (GraphRAG 核心适配层)
       -> workspace.py (环境准备)
       -> query_engine.py (Python API 查询)
       -> index_runner.py (CLI 子进程索引)
       -> projectors/ (视图投影)
```

## 2. 知识引擎层 (`novel_system/graphrag_app/`)

这是本次迁移的核心新增包，负责与 Microsoft GraphRAG 引擎交互。

| 模块 | 职责 |
|---|---|
| `workspace.py` | 管理每本书的 GraphRAG 运行环境，处理路径初始化和状态查询。 |
| `input_builder.py` | 将小说原始 TXT 或章节 JSON 转换为 GraphRAG 标准 `input/*.txt` 文件。 |
| `settings_builder.py` | 自动生成 `settings.yaml`，配置本地 Embedding Server、MiniMax API 及实体抽取类型。 |
| `index_runner.py` | 封装 GraphRAG CLI，通过 `subprocess` 启动异步索引构建任务。 |
| `query_engine.py` | 封装 GraphRAG Python API，执行 Local/Global/DRIFT/Basic 搜索。 |
| `query_router.py` | 根据用户问题自动路由到最合适的查询模式。 |
| `answer_adapter.py` | 将 GraphRAG 的原始查询结果转换为 API 契约要求的 `AskResponse`。 |
| `table_loader.py` | 负责读取 GraphRAG 输出的 Parquet 表（entities, relationships 等）。 |
| `graph_projector.py` | 将实体和关系表投影为前端可渲染的交互式图谱 JSON。 |
| `timeline_projector.py` | 将 covariates (事件) 和 text_units 投影为全书时间线。 |

## 3. 业务服务层 (`novel_system/services/`)

通过 Mixin 模式为 `NovelSystemService` 注入具体业务逻辑。

### 3.1 `indexing.py` (索引流水线)
- **入口**: `_run_book_index(book_id)`
- **流程**:
  1. 调用 `graphrag_workspace.prepare()` 初始化环境。
  2. 调用 `graphrag_input_builder.build_from_txt()` 准备语料。
  3. 调用 `graphrag_settings_builder.build()` 生成配置。
  4. 调用 `graphrag_index_runner.run()` 执行重量级索引构建（CLI）。
  5. 调用 `graph_projector` 和 `timeline_projector` 生成派生视图。

### 3.2 `qa.py` (智能问答)
- **入口**: `ask(book_id, request)`
- **流程**:
  1. 调用 `graphrag_query_router.route()` 决定搜索模式。
  2. 调用 `graphrag_query_engine.search()` 获取 GraphRAG 知识。
  3. 调用 `graphrag_answer_adapter.to_ask_response()` 封装结果。
- **注意**: 该方法已全面转为 `async` 以适配 GraphRAG Python API。

### 3.3 `continuation.py` (续写)
- **当前状态**: 已降级。
- **说明**: 迁移期间仅返回升级提示，未来将利用 `graphrag_basic` 模式提取文风样本。

## 4. 数据基础设施层

### 4.1 `indexing/` 子包
- **repository.py**: 管理书籍 manifest 和本地文件存储。
- **parser.py**: 负责将原始小说 TXT 解析为章节结构，为 `input_builder` 提供输入。

### 4.2 `llm.py`
- 封装 `MiniMaxClient`，作为 LiteLLM 的上游提供商，支持 API Key 认证和指数退避重试。

### 4.3 `config.py`
- 统一管理环境变量，包括 GraphRAG 专用的模型名称、API Base 和超时设置。

## 5. 交互图谱与时间线 (`graph_service.py`)

- **交互图谱**: 弃用旧有的 `relationship_graph.json`，改为从 GraphRAG 的 `entities.parquet` 和 `relationships.parquet` 动态投影。
- **正典管理 (Canon)**: 支持将 GraphRAG 提取的知识与用户自定义的正典记忆进行对比。

## 6. 模块边界与清理计划

| 模块 | 迁移后地位 | 清理建议 |
|---|---|---|
| `retrieval.py` | **Legacy** | 仅保留类型定义，建议下个版本彻底删除。 |
| `validator.py` | **部分保留** | `SpoilerGuard` 已移除，`EvidenceGate` 正在适配 GraphRAG。 |
| `planner.py` | **部分保留** | 主要用于意图识别，scope 过滤逻辑已废弃。 |
| `semantic_scorer.py` | **部分保留** | 仅用于辅助验证，不再参与检索排序。 |
