## 项目定位

**小王一号**是一个**基于 Microsoft GraphRAG 的长篇小说智能工作台**（Long-form Fiction Workspace），面向小说深度分析、多模态问答、结构化图谱投影和事件时间线追踪。

核心能力：
- **GraphRAG 索引构建**：自动将小说解析为 documents、text_units，并提取 entities、relationships、covariates，构建社区报告。
- **多模式智能问答 (Ask)**：
  - `Local Search`：针对特定人物、物品、关系或局部情节的精准查询。
  - `Global Search`：针对全书主题、主线、势力格局或整体总结的全局分析。
  - `DRIFT Search`：针对复杂因果、多跳推理和跨社区关联的深度检索。
  - `Basic Search`：基于原文片段和关键词的快速定位。
- **交互式图谱投影**：基于 GraphRAG 实体和关系表生成的力导向图，支持中心人物聚焦。
- **事件时间线投影**：基于 covariates 和 text_units 派生的全书事件脉络。
- **受约束续写 (预览)**：利用 GraphRAG 上下文提供文风和剧情一致的续写（当前处于降级预览阶段）。

## 一句话架构

```
Dashboard (HTML/JS) → FastAPI → NovelSystemService → GraphRAG (QueryEngine / IndexRunner / Workspace)
```

## 项目类型

- **后端为主**的全栈项目
- 后端：Python + FastAPI
- 前端：服务端渲染 Jinja2 模板 + 原生 JS（无框架）
- 知识引擎：Microsoft GraphRAG v3.0.9 (Python API & CLI)

## 当前可运行能力

| 能力 | 状态 | 说明 |
|------|------|------|
| 书籍导入 | 可用 | 支持 .txt 文件上传或本地注册 |
| GraphRAG 索引构建 | 可用 | 自动化 Workspace 准备、Input 构建、Settings 生成、CLI 索引和 Parquet 验证 |
| 多模式问答 (Ask) | 可用 | 集成 Local/Global/DRIFT/Basic 四种搜索模式 |
| 人物关系图谱 | 可用 | 基于 entities/relationships Parquet 表派生生成 |
| 事件时间线 | 可用 | 基于 covariates/text_units Parquet 表派生生成 |
| 存储与 Token 统计 | 可用 | 实时监控 GraphRAG 运行产物和 LLM 消耗 |

## 当前已知风险

| 风险 | 严重程度 | 说明 |
|------|----------|------|
| Indexing 资源消耗 | 高 | GraphRAG 索引构建需要大量 LLM 调用和本地 Embedding 计算，耗时较长 |
| 续写功能降级 | 中 | 续写功能正在迁移至 GraphRAG 链路，目前仅返回降级提示 |
| 遗留死代码 `static/app.js` | 低 | 前端重构为 ESM 模块（位于 `static/js/`）已完成，但遗留 `app.js` 用于保证部分旧测试正常运行，后续需清理 |
| 环境变量依赖 | 中 | 高度依赖本地 Embedding Server 和 MiniMax API |

## 技术栈速览

| 维度 | 选型 |
|------|------|
| 语言 | Python 3.12+ |
| 核心引擎 | Microsoft GraphRAG v3.0.9 (editable install) |
| Web 框架 | FastAPI + Uvicorn |
| 模板引擎 | Jinja2 |
| 数据处理 | Pandas + PyArrow + PyYAML |
| LLM | MiniMax API (LiteLLM 兼容) |
| Embedding | 本地 OpenAI-compatible Server (OpenVINO 加速) |
| 向量存储 | GraphRAG 内部向量管理 |
| 图谱分析 | NetworkX |
| 数据模型 | Pydantic v2 |
| 测试 | pytest |
| 包管理 | requirements.txt + conda (环境名 chaishu) |
