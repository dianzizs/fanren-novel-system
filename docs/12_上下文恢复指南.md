# 12 上下文恢复指南

> 版本：1.0 | 创建日期：2026-05-23
> 本文档解决一个核心问题：每次打开项目时，AI 如何在最短时间内恢复完整上下文，避免因遗忘设计决策而引入错误。

---

## 一、下次打开项目时 AI 必须先读的文件

按顺序阅读，每个文件都有明确目的，不得跳过：

| 顺序 | 文件 | 读完后你应该知道 |
|------|------|-----------------|
| 1 | `docs/09_变更记录.md` | 上次做了什么，当前代码处于什么状态 |
| 2 | `docs/10_待办与风险.md` | 有哪些 P0/P1 风险悬而未决，不能踩 |
| 3 | `docs/00_项目总览.md` | 项目定位、架构一句话、当前可用能力 |
| 4 | `docs/01_目录结构说明.md` | 每个文件的用途和状态 |
| 5 | `docs/03_核心模块说明.md` | 各模块职责、边界、已知问题 |
| 6 | `AGENTS.md` | 本次开发的行为规则 |

如果任务明确，步骤 3-5 可以只读与任务相关的部分，但步骤 1、2、6 必须完整阅读。

### 恢复上下文的标准提示词

```
请按顺序阅读以下文件，完整掌握项目上下文后再开始工作：
1. docs/09_变更记录.md
2. docs/10_待办与风险.md
3. docs/00_项目总览.md
4. docs/01_目录结构说明.md
5. docs/03_核心模块说明.md
6. AGENTS.md

阅读完成后，输出：
- 当前项目状态（一句话）
- 上次未完成的事项（如有）
- 本次任务涉及的模块
- 需要注意的风险
```

## 二、如何快速恢复项目上下文

### 2.1 五分钟快速定位法

如果时间紧，只读这三个文件可以覆盖 80% 的上下文：

1. `docs/09_变更记录.md` — 最后几条记录告诉你"上次停在哪里"
2. `docs/10_待办与风险.md` — P0 风险告诉你"什么地方不能乱动"
3. `docs/00_项目总览.md` — 架构一句话告诉你"整体是什么"

### 2.2 架构一句话（随时可用）

```
Dashboard (HTML/JS) → FastAPI (api.py) → NovelSystemService (service.py)
  → Planner (planner.py)
  → Retrieval (retrieval.py) → VectorStore / TF-IDF / Reranker
  → Validator (validator.py) → EvidenceGate / AnswerValidator / SpoilerGuard
  → LLM (llm.py) → MiniMax API → Mimo API（降级）
  → GraphService (graph_service.py) → NetworkX
  → IndexRepository (indexing.py) → FAISS + TF-IDF + LLM 提取
```

### 2.3 关键文件速查

| 要改什么 | 先读哪个文件 |
|----------|-------------|
| API 路由 | `novel_system/api.py` + `docs/02_技术栈与启动流程.md` |
| 问答逻辑 | `novel_system/service.py` + `docs/03_核心模块说明.md` |
| 检索行为 | `novel_system/retrieval.py` + `novel_system/search/orchestrator.py` |
| 验证逻辑 | `novel_system/validator.py` |
| 索引构建 | `novel_system/indexing.py`（注意：约 1900 行，职责过重） |
| 前端页面 | `templates/dashboard.html` + `static/app.js` |
| LLM 调用 | `novel_system/llm.py` + `.env`（API Key 在此） |
| 图谱功能 | `novel_system/graph_service.py` + `novel_system/graph_name_policy.py` |

## 三、如何判断当前任务涉及哪些模块

### 3.1 按功能区域定位

| 用户描述的任务 | 涉及的核心文件 |
|----------------|----------------|
| "问答结果不准" | `planner.py`、`retrieval.py`、`validator.py`、`service.py` |
| "续写质量差" | `service.py` → `continuation.py`、`validator.py` 中的 SpoilerGuard |
| "导入书籍失败" | `indexing.py`、`api.py` 中的 import 路由 |
| "图谱显示异常" | `graph_service.py`、`graph_name_policy.py`、`static/app.js` |
| "Dashboard 页面问题" | `templates/dashboard.html`、`static/app.js`、`static/styles.css` |
| "API 接口报错" | `api.py`、`models.py`、对应的 service 文件 |
| "Embedding 慢或失败" | `novel_system/embedding/` 目录下的文件 |
| "测试失败" | 对应的 `tests/test_*.py` + 被测模块 |

### 3.2 模块边界注意事项（来自 docs/03_核心模块说明.md）

以下边界问题已知，修改时必须注意：

- `indexing.py` 职责过重（约 1900 行），改动风险高，必须先读完整文件
- `validator.py` 包含 4 个组件（EvidenceGate、AnswerValidator、ContinuationValidator、SpoilerGuard），改一个可能影响其他三个
- `service.py` 是所有业务逻辑的汇聚点，改动前必须理解完整调用链
- `static/app.js` 单文件承担所有前端逻辑，改动时注意不要破坏其他功能区域

## 四、如何避免 AI 遗忘之前的设计决策

### 4.1 设计决策的存储位置

| 决策类型 | 存储位置 |
|----------|----------|
| 技术选型理由（为什么用 MiniMax 而不是 OpenAI） | `docs/00_项目总览.md` |
| 模块职责划分（为什么 validator 包含 SpoilerGuard） | `docs/03_核心模块说明.md` |
| 文件删除决策（为什么删了某个文件） | `docs/09_变更记录.md` 中的 delete 条目 |
| 已知风险和暂缓处理的决定 | `docs/10_待办与风险.md` |
| 接口设计决策 | `docs/02_技术栈与启动流程.md` |
| 行为规则和约束 | `AGENTS.md` |

### 4.2 防止遗忘的操作规范

**每次做完任何决策，立即写入对应文档。** 不要依赖对话历史，对话历史会消失。

具体做法：

1. **决定不做某件事时**：在 `docs/10_待办与风险.md` 中记录"暂缓原因"
2. **决定某个架构方向时**：在 `docs/00_项目总览.md` 或 `docs/03_核心模块说明.md` 中更新说明
3. **删除文件时**：在 `docs/09_变更记录.md` 中记录删除理由，在 `docs/01_目录结构说明.md` 中标记已删除
4. **修改接口时**：立即更新 `docs/02_技术栈与启动流程.md` 中的路由表

### 4.3 长任务拆分原则

如果一个任务需要多次对话才能完成：

1. 在开始时在 `docs/10_待办与风险.md` 中新增一条"进行中"的任务条目
2. 每次对话结束时，在 `docs/09_变更记录.md` 中记录"本次完成了什么、下次从哪里继续"
3. 下次对话开始时，先读 `docs/09_变更记录.md` 最后几条，找到"下次从哪里继续"的标记

### 4.4 上下文恢复的验证方法

读完文档后，AI 应该能回答以下问题，如果回答不了说明上下文不足，需要继续阅读：

- 项目的启动命令是什么？（答：`conda run -n chaishu python start_server.py`）
- 问答链路经过哪些模块？（答：Planner → Retrieval → Validator → LLM）
- 当前最高优先级的风险是什么？（答：见 `docs/10_待办与风险.md` P0 列表）
- 上次改了什么？（答：见 `docs/09_变更记录.md` 最后几条）
- `indexing.py` 为什么要小心？（答：约 1900 行，职责过重，改动风险高）

## 五、项目关键约定速查

| 约定 | 内容 |
|------|------|
| Python 环境 | conda 环境名 `chaishu`，所有命令前加 `conda run -n chaishu` |
| 启动命令 | `conda run -n chaishu python start_server.py`（不是 `python -m novel_system.api`） |
| 测试命令 | `conda run -n chaishu python -m pytest` |
| LLM 主力 | MiniMax API，降级到 Mimo API |
| Embedding | 本地 OpenVINO，模型 BAAI/bge-small-zh-v1.5 |
| 前端技术 | 原生 HTML/CSS/JS，无框架，无构建流程 |
| 数据存储 | `data/books/<书名>/` 下的 `.json` + `.pkl` artifact 文件 |
| 文档语言 | 中文，技术术语保留英文 |
| 提交格式 | `<type>(<scope>): <subject>`，中文 subject |
