# 02 技术栈与启动流程

> 生成日期：2026-05-25

## 1. 项目类型

**后端为主的全栈项目**。后端使用 Python + FastAPI，前端为服务端渲染的 Jinja2 模板 + 原生 JS，无独立前端构建流程。核心知识引擎已迁移至 Microsoft GraphRAG。

## 2. 技术栈详情

### 2.1 语言与运行时

| 维度 | 选型 | 说明 |
|------|------|------|
| 主语言 | Python | 全部后端逻辑 |
| Python 版本 | 3.12+ | |
| Conda 环境名 | `chaishu` | AGENTS.md 约定使用 `conda run -n chaishu python ...` |
| 前端语言 | HTML / CSS / 原生 JS | 无 TypeScript、无框架 |

### 2.2 核心引擎与框架

| 维度 | 选型 | 来源 |
|------|------|------|
| 知识引擎 | Microsoft GraphRAG v3.0.9 | 本地 editable install (D:\pythonProject\graphrag) |
| HTTP 框架 | FastAPI | `requirements.txt` |
| ASGI 服务器 | Uvicorn | `requirements.txt` |
| 模板引擎 | Jinja2 | `requirements.txt` |
| 数据处理 | Pandas + PyArrow + PyYAML | 支撑 GraphRAG Parquet 表处理 |

### 2.3 包管理

| 工具 | 用途 |
|------|------|
| `requirements.txt` | Python 依赖声明 (包含 pandas, pyarrow, pyyaml 等) |
| conda | 环境管理 (环境名 `chaishu`) |
| pip | 包安装 (graphrag 通过 `pip install -e` 安装) |

### 2.4 路由方案

**后端路由**：FastAPI 路由，集中在 `novel_system/api.py`。

核心 API 清单（共 20 个活跃路由）：

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/` | Dashboard 页面 |
| GET | `/api/books` | 列出所有注册的书籍及状态 |
| POST | `/api/books` | 注册新书籍（支持本地文件注册或上传文件） |
| DELETE | `/api/books/{book_id}` | 删除指定书籍的所有数据与索引 |
| POST | `/api/books/{book_id}/index` | 同步触发书籍索引分析（旧默认流程） |
| GET | `/api/books/{book_id}/status` | 获取书籍的索引及分析进度 |
| POST | `/api/books/{book_id}/start-index` | 异步启动 GraphRAG 索引分析流程 |
| GET | `/api/books/{book_id}/artifacts` | 获取书籍生成的所有 Parquet 产物目录 |
| GET | `/api/books/{book_id}/artifacts/{artifact_name}` | 读取特定 Parquet 产物内容 |
| GET | `/api/books/{book_id}/reader` | 获取阅读器数据（含目录、当前章、Top人物、事件等） |
| POST | `/api/books/{book_id}/ask` | GraphRAG 多模式问答（支持 Auto/Local/Global/DRIFT/Basic） |
| POST | `/api/books/{book_id}/continue` | 书籍受约束续写接口（当前处于降级预览） |
| GET | `/api/books/{book_id}/canon` | 获取书籍的正典设定或记忆列表 |
| PUT | `/api/books/{book_id}/canon` | 更新书籍的自定义正典记忆 |
| GET | `/api/books/{book_id}/timeline` | 获取书籍的事件时间线（基于 covariates 追踪投影） |
| GET | `/api/books/{book_id}/graph` | 获取书籍的交互式关系图谱（基于 entities/relationships 投影） |
| GET | `/api/dashboard` | 获取全局看板统计数据（藏书数、耗时、Token等） |
| GET | `/api/storage-stats` | 获取服务器存储占用统计（索引、上传等） |
| GET | `/api/token-stats` | 获取全局及按书划分的 LLM Token 使用统计 |
| POST | `/v1/embeddings` | OpenAI 兼容的本地 Embedding 生成接口 |

### 2.5 状态管理

- **后端**：`NovelSystemBase` 维护 GraphRAG Workspace、QueryEngine 和 IndexRunner 的单例。
- **前端**：`static/js/main.js`（基于 ES Modules）维护 UI 状态和异步任务轮询；`static/app.js` 为遗留死代码。

### 2.6 LLM 与 Embedding

- **LLM**: MiniMax API (通过 LiteLLM 兼容层调用)。
- **Embedding**: 本地 OpenAI-compatible Server (OpenVINO/CUDA 加速)。

## 3. 启动流程

### 3.1 开发环境启动

```bash
# 1. 激活 conda 环境
conda activate chaishu

# 2. 安装 GraphRAG (确保本地源码路径正确)
pip install -e D:\pythonProject\graphrag\packages\graphrag

# 3. 启动服务
python start_server.py
```

服务启动后访问 `http://localhost:8000`。

### 3.2 启动流程详解

```
start_server.py
  └─ novel_system.api:app
     └─ create_app()
        ├─ config = AppConfig.load()
        ├─ service = create_service()
        │   └─ return GraphService()
        │      └─ NovelSystemBase.__init__()
        │         ├─ graphrag_workspace = GraphRAGWorkspace(config)
        │         ├─ graphrag_query_engine = GraphRAGQueryEngine(config)
        │         ├─ graphrag_index_runner = GraphRAGIndexRunner(config)
        │         ├─ graph_projector = GraphRAGGraphProjector(config)
        │         └─ timeline_projector = GraphRAGTimelineProjector(config)
        └─ 注册 FastAPI 路由 (@app.post("/api/books/{book_id}/ask") 等)
```
